# Adding a language to serialhub

serialhub is bilingual by design: **English is the default**, Simplified Chinese
ships alongside it, and a new language is a **drop-in file** on each surface (Web
UI, backend, docs). You never edit core code to add one.

This guide documents the frozen i18n conventions so a contributor can add a
language without touching `app.js`, `server.py`, or any other core file.

> Pattern: **one file per locale.** Each surface has a canonical English source
> (`en`) and additional locales sit next to it. Missing keys fall back to `en`.
> Web UI contract lives in [`../serialhub/static/i18n/en.js`](../serialhub/static/i18n/en.js)
> and [`../serialhub/static/i18n/_template.js`](../serialhub/static/i18n/_template.js).

---

## 1. The three surfaces

| Surface | English source | A locale adds | Language set by |
|---|---|---|---|
| Web UI | `serialhub/static/i18n/en.js` | `serialhub/static/i18n/<lang>.js` | registry + `localStorage['serialhub.lang']` |
| Backend | `serialhub/i18n/en.json` | `serialhub/i18n/<lang>.json` | `SERIALHUB_LANG` env, else HTTP `Accept-Language` |
| Docs | `README.md`, `docs/<NAME>.md` | `README.<lang>.md`, `docs/<NAME>.<lang>.md` | the reader picks a file |

The `en` file of each surface is the **key-set source of truth**: every other
locale must carry the exact same keys.

---

## 2. Web UI: a locale is one file

The registry is defined **inline in `index.html`** as `window.SERIALHUB_I18N`:

```js
window.SERIALHUB_I18N = window.SERIALHUB_I18N || {
  _d: {}, _meta: {},
  register: function(code, dict, meta){ this._d[code] = dict; this._meta[code] = meta || {}; },
  has: function(code){ return !!this._d[code]; },
  langs: function(){ return Object.keys(this._d); },
  meta: function(code){ return this._meta[code] || {}; },
  dict: function(code){ return this._d[code] || {}; }
};
```

A locale file registers its dictionary and metadata in one call:

```js
window.SERIALHUB_I18N.register('<lang>', {
  // ...the exact same keys as en.js, with translated values...
}, { label: 'XX', htmlLang: 'xx-XX', name: '…' });
```

- `code` is the registry key **and** the value persisted in
  `localStorage['serialhub.lang']` (e.g. `de`, `pt-BR`).
- `dict` is a flat `key -> string` map. Keys must be **identical to `en.js`**.
  Values may contain `{name}` placeholders; keep placeholders verbatim (same
  spelling and braces) across languages. `t(key, vars)` interpolates them.
- `meta` carries the switcher and document metadata:
  - `label`    short button text in the top-bar switcher (keep it 2-4 chars).
  - `htmlLang` the value written to `<html lang>` (e.g. `de`, `pt-BR`).
  - `name`     human-readable language name (e.g. `Deutsch`).

The top-bar switcher **auto-populates from the registry**: one button per
registered locale appears automatically, so you add no HTML for the button.

### Wiring it in

Add **one line** to `index.html`, after the other locale `<script>` tags and
**before `app.js`** (load order among locales does not matter; the active locale
is chosen at runtime):

```html
<script src="/static/i18n/<lang>.js"></script>
```

Start from [`../serialhub/static/i18n/_template.js`](../serialhub/static/i18n/_template.js):
copy it to `serialhub/static/i18n/<lang>.js`, fill in the `register()` call, and
delete the template comment.

---

## 3. Backend: a catalog is one JSON file

A backend catalog is `serialhub/i18n/<lang>.json` with the **same key set** as
`serialhub/i18n/en.json`. The active locale is resolved as:

1. the `SERIALHUB_LANG` environment variable, if set; else
2. the request's HTTP `Accept-Language` header; else
3. the default, `en`.

Keys missing from the chosen catalog fall back to `en`.

---

## 4. Docs: an English file plus siblings

Documentation follows the same one-file-per-locale pattern:

| English | Locale |
|---|---|
| `README.md` | `README.<lang>.md` (e.g. `README.zh-CN.md`) |
| `docs/<NAME>.md` | `docs/<NAME>.<lang>.md` (e.g. `docs/MCP.zh-CN.md`) |

Put a **language switch bar as the very first line** of every localized file,
for example:

```markdown
**English** · [简体中文](README.zh-CN.md)
```

and its counterpart:

```markdown
**简体中文** · [English](README.md)
```

Point internal doc links at the correct-language file (a Chinese README should
link `docs/MCP.zh-CN.md`, not `docs/MCP.md`).

> Note: [`ARCHITECTURE.md`](ARCHITECTURE.md) is currently **Chinese-only**; there
> is no English translation of it yet, so links to it stay as-is.

---

## 5. Add a language in 3 steps

1. **Web UI**: copy `serialhub/static/i18n/_template.js` to
   `serialhub/static/i18n/<lang>.js`, fill in `register()` with the same keys as
   `en.js`, and add one `<script src="/static/i18n/<lang>.js"></script>` line to
   `index.html` before `app.js`.
2. **Backend**: copy `serialhub/i18n/en.json` to `serialhub/i18n/<lang>.json` and
   translate the values, keeping every key.
3. **Docs**: add `README.<lang>.md` and, per translated page,
   `docs/<NAME>.<lang>.md`, each starting with the language switch bar.

---

## 6. Verify

Run both checks before submitting:

```powershell
# key parity across backend catalogs + Web UI locales
python tools/i18n_check.py

# the i18n test suite
python -m pytest tests/test_i18n.py
```

`tools/i18n_check.py` compares each locale's key set against `en` and reports any
missing or extra keys, across both `serialhub/i18n/*.json` and
`serialhub/static/i18n/*.js`.

> **Keep key sets in sync.** A missing key does **not** break the UI: the Web UI
> fallback chain is `active locale -> en -> the key itself`, and the backend
> falls back to `en`. But parity keeps translations honest and lets
> `tools/i18n_check.py` pass clean.
